# 外部 MCP 服务器

这个工程可以借用「别人的工具」：把外部 MCP（Model Context Protocol）服务器连起来，把它 `tools/list`
里的工具注册进本工程的工具表，模型就能像调用本地工具一样调用它们。反方向的另一件事（把本工程的工具
递给外部模型）在 `mcp_server.py`，两件事互不相干。

界面入口在**独立设置页 → 「MCP 服务器」分组**（启动页或工作区导航底部的「设置」都能进去）；
配置文件在用户目录，跨工程共用，不写进任何工程文件。

## 这是什么、为什么要它

- 模型侧只看见一张工具表。外部服务器发现的工具会带着原来的名字说明与参数 schema 进这张表，
  调用时原样转发给远端，结果折成一段文本回来。
- 服务器按需启动：一条 stdio 会话（子进程）在第一次真正需要时建起来，之后复用；应用退出时收掉。
- 外部工具是附加能力：一台服务器坏掉不影响本地工具，也不影响别的服务器。

## 配置放在哪

| 文件 | 默认位置 | 作用 |
| --- | --- | --- |
| 服务器清单 | `~/.narrative/mcp-servers.json` | 人手可改的唯一配置源 |
| 工具缓存 | 与清单同目录的 `mcp-tools-cache.json` | 上次成功发现的工具名/schema，启动时先顶上 |
| 损坏备份 | `mcp-servers.json.bak` | 保存时若旧文件读不懂，先备份成这个再覆盖 |

- 整体换位置用环境变量 `NARRATIVE_MCP_FILE`（指到清单文件路径，缓存跟着它同目录）。测试与便携版靠它隔离，绝不碰真实用户目录。
- 界面上「配置文件：…」那一行显示的就是当前实际路径——改的是哪个文件，以它为准。
- 每次保存都是原子写（先写临时文件再替换），不会留下半个配置文件。

## 字段含义

```json
{
  "version": 1,
  "servers": [
    {
      "name": "本地笔记",
      "enabled": true,
      "transport": "stdio",
      "command": "C:\\Python312\\python.exe",
      "args": ["C:\\tools\\notes_server.py", "--stdio"],
      "env": {"NOTES_DIR": "D:\\notes"},
      "cwd": "C:\\tools",
      "timeout": 20
    },
    {
      "name": "remote",
      "enabled": false,
      "transport": "http",
      "url": "https://example.invalid/mcp",
      "timeout": 20
    }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `name` | 身份，同时是工具名前缀。同一份配置里不能重名（重名会让整份配置读不出来）。 |
| `enabled` | 只有启用的服务器才会被连接；停用的仍留在列表里，界面上标「已停用」，不算错误。 |
| `transport` | `stdio`（起子进程，按行说 JSON-RPC）或 `http`（Streamable HTTP，见下文）。 |
| `command` | stdio 的启动命令。Windows 上建议给完整路径或带扩展名的可执行文件，`npx` 这类要确认在 PATH 里。 |
| `args` | 参数数组。 |
| `env` | 追加/覆盖子进程的环境变量（不是整份替换）。 |
| `cwd` | 子进程的工作目录；留空沿用当前工作目录。 |
| `url` | http 的端点地址，必须是 `http://` 或 `https://` 的完整地址（例如 `http://127.0.0.1:8765/mcp`）。 |
| `timeout` | 单次请求等多久（秒，默认 20）。握手、`tools/list`、`tools/call` 都按它算。 |

界面上「参数」一栏是空格分隔的一行，保存时按下面的规则切分：

- 空格/制表符分隔；带空格的一段用**一对双引号**护住，例如 `server.py --mode "stdio fake"`。
- 不支持引号嵌套、单引号、反斜杠转义。需要这些写法就直接改配置文件（那里是数组，写什么就是什么）。
- 引号没配对会当场报错并说明原因，不会替你猜一个别的切法。

「环境变量」一栏是「每行一条 `K=V`」：空行与 `#` 开头的注释跳过，值里可以再出现 `=`。

## 工具如何命名

远端工具名进表时统一加前缀：`mcp__<服务器名>__<远端工具名>`。

- 服务器名与工具名里除 `[A-Za-z0-9_]` 以外的字符一律折成下划线，首尾下划线去掉：`my server.b` + `read-file` → `mcp__my_server_b__read_file`。
- 折叠后撞名（两台服务器名折叠后相同，或同一台远端自己有 `a.b` / `a-b`）会依次加 `_2`、`_3`。
- 前缀是硬边界：模型和人都能一眼看出这是外部工具；刷新时“原地换合同”也靠它认出哪些是自己的。

## 只读 / 写的判定

- 远端在 `tools/list` 里明确声明 `annotations.readOnlyHint === true`，这个工具才算**只读**；
- 其它情况（没声明、声明 false、字段缺）一律按**写**处理——宁可多要一次确认，也不能让有副作用的远端调用从只读通道溜过去。
- 缓存里连 `annotations` 一起存，就是为了重启后这条判定不退化。

## 缓存与刷新时机

| 时机 | 发生什么 |
| --- | --- |
| 应用启动 | 只读缓存注册工具，**不连服务器**。启动不能等握手和超时；界面先显示「上次发现了什么」。 |
| 点「保存」 | 先落盘（同步、原子写），再在后台线程里收掉旧会话并重连所有启用的服务器，完成后发 `mcpServersChanged` 让面板重读。 |
| 点「刷新工具」 | 后台重连 + 重发现；结果一句话提示（几台、几个工具、几台报错）。 |
| 点「测试连接」 | 同一次后台刷新，但结果**逐台**列出来（正常/失败原因），错误也留在这台服务器那一行。 |
| 应用退出 | 收掉所有子进程（先关输入让服务器自己收尾，超时再 terminate/kill）。 |

- 刷新期间界面禁用保存/编辑/开关，避免同一份配置被两个刷新线程撕开。
- 单台失败只写在它自己那一行；配置本身读不懂（坏 JSON、字段不对、重名）才会成为整块面板的错误。
- 启动期缓存/配置读失败会留痕在 `tool_api.MCP_STARTUP_ERROR`，面板顶部以「上次启动读取外部工具时失败：…」显示。
- 从列表里删掉（或改名）一台服务器后，它的工具会立刻从工具表撤掉——不撤的话模型还能调用它，而一调用又会把这台已经不存在的服务器重新拉起来。

## Streamable HTTP（单端点）

`transport: "http"` 的服务器按 MCP 2025-06-18 的 Streamable HTTP 连：只用一个端点 URL，每件事都是一次
`POST`，响应可能是 `application/json`（一整条 JSON-RPC 响应），也可能是 `text/event-stream`（SSE 流，
里面可能先有别的通知、再是这次请求的响应）。两种都收。

```json
{ "name": "remote", "enabled": true, "transport": "http",
  "url": "http://127.0.0.1:8765/mcp", "timeout": 20 }
```

- `url` 必须是 `http://` 或 `https://` 的完整地址；写错在**读配置**那一步就报错并指名第几项、哪台服务器，
  不会拖到连接时才说「连不上」。
- 握手时服务器若在响应头里给 `Mcp-Session-Id`，之后每个请求都回带它；`initialize` 之后的请求还会带
  `MCP-Protocol-Version: 2025-06-18`。`notifications/initialized` 只要求 202，不要求 body。
- 收会话时如果手里有 session id，会向同一端点发一次 `DELETE`（失败忽略，最长等 2 秒）。
- `timeout` 管的是「一条请求发出到拿到它自己的那条响应」。服务器用心跳吊着连接不算数：截止时间按本地时钟算。
- 目前**不**做服务端主动推的 GET 流、也不做 `Last-Event-ID` 断线续传；SSE 流里不是本次请求响应的消息
  （别的 id、服务器通知）直接忽略。本客户端也不发自定义鉴权头。

两种传输的差别：

| | stdio | http |
| --- | --- | --- |
| 怎么连 | 起子进程（`command` + `args`） | 一个 `url`，按需 POST |
| 会话身份 | 子进程本身 | 响应头 `Mcp-Session-Id` |
| 收尾 | 关 stdin → 等 → terminate/kill | 带 session id 的 `DELETE` |
| 何时作废 | 进程退出 / 超时 / 写不进 | 超时、连接层失败、404（4xx/5xx 与 JSON-RPC error 不作废） |
| 其余一致 | 握手、`tools/list` 分页、工具前缀与只读写判定、缓存、刷新时机 | 同左 |

## 常见失败怎么排查

| 现象（面板上的话） | 多半是什么 | 怎么处理 |
| --- | --- | --- |
| 配置文件 … 不是合法 JSON | 手改时少了个括号/逗号 | 按提示改好那个文件；或直接在面板里保存一次（旧文件会备份成 `.bak`） |
| 服务器重名：… | 两条 `name` 完全一样 | 改成不同名字。重名会让整份配置读不出来，所以保存时直接拒绝 |
| MCP 服务器 X 启动失败：找不到命令 … | `command` 不在 PATH、没写扩展名、路径带引号 | 给绝对路径或带扩展名的可执行文件；Windows 上先确认在终端里能直接跑起来 |
| MCP 服务器 X 超时：… | 进程起来了但不说协议（例如把日志打在 stdout 却没进入握手），或 `timeout` 太小 | 先调大 `timeout`；再确认 `args` 真的指向一个 MCP stdio 服务器 |
| MCP 服务器 X 的输出流已关闭 / 进程已退出 | 服务器崩了、或者它以为客户端已经走开 | 看这台服务器自己的日志（它的 stderr 被丢弃，不会进界面）；用它的命令行单跑一次 |
| 工具名已被本地工具占用 | 极端巧合：本地工具就叫 `mcp__…` | 给服务器改个名字 |
| 某台服务器显示「已停用」 | `enabled=false` | 打开开关即可；停用不是错误 |
| 面板里 0 个工具但没有错误 | 还没刷新过，缓存里也没有 | 点「测试连接」看逐台结果 |
| MCP 服务器 X 连不上 http://… | 端口没开、服务没起、地址或路径写错 | 先用浏览器或 curl 打同一个 URL；注意路径（有的服务器是 `/mcp`，有的是别的） |
| … 的 tools/list 被拒绝：HTTP 400 … | 会话头没被接受，或服务器要求先握手 | 点「刷新工具」重新握手；仍失败就看服务器日志（它可能要鉴权头，本客户端目前不发） |
| … 的 tools/list 被拒绝：HTTP 404 | 会话过期或被重置（服务器重启常见） | 会话已作废，下次调用会自动重新 `initialize`；频繁出现说明服务器会话活得很短 |
| … 回给 tools/list 的不是 JSON（Content-Type: text/html …） | URL 指到了网页或登录页 | 换到真正的 MCP 路径；消息末尾带的是服务器原话片段 |
| … 在 N 秒内没有回应 tools/call | 服务器在算，或一直发心跳不给答案 | 调大这台服务器的 `timeout` |
| 列表为空但配置文件里明明有 | 文件路径不是面板显示的那一个（例如设了 `NARRATIVE_MCP_FILE`） | 以面板上的配置路径为准 |

排查顺序建议：先看这台服务器那一行的错误 → 再按它给的命令在终端里手动跑一次 → 最后才看缓存文件。
缓存只是「上次成功的样子」，删掉它不影响正确性，只影响下次启动时列表里有没有东西。
