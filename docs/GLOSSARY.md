# 术语表

本表收录 `docs/MODEL.md` 与提取提示词（`extraction` v23）里出现、且**容易互相顶替**的概念。词条编号 `G-01…G-21` 只在本表内使用；每条后面的 `M-xx` 是 [叙事模型](MODEL.md) 里的**规则编号**（`M-01` 事件边界、`M-16` 容器属性让位等），只引用、不改写。不变量编号 `I-xx` 由 test-conventions 维护，本表不引用。

每条写成三列对照：先读「是什么」，再看右列的最短反例。同一概念只在一处定义，别处用编号引用。

## 1 五层结构

| 概念 | 是什么（G-xx ＋ 规则引用） | 不是什么 / 易混 |
| --- | --- | --- |
| 阅读位置 | **G-01** 由来源顺序 `source_order` 与 Unicode 偏移组成的先后坐标 `{source_id, start}`；跨层比较先后一律看它（MODEL §1） | 不是编号顺序（`E1`、`E2` 只表身份）；不是录入时间；不是章节、切片或批次，它们只作阅读索引与处理范围（`M-06`） |
| 事件 | **G-02** 介于场景与动作之间、可独立概括的情节单元，有自身起因、推进与落点；边界看能否独立概括、拿掉后前后是否仍成立（`M-01`） | 不是句子、段落或动作链；不是一次属性变化；引文数量也不决定边界（`M-13`）；只剩实施步骤时归入所属事件 |
| 动作 | **G-03** 事件的实施细节，直属恰好一个同语境事件，是最小包含层级；只在明确要求时提取（`M-05`） | 不是更小的事件；不是每个动词一条；两档粒度都默认不提取 |
| 场景 | **G-04** 一组空间上接近、时间上连续的事件的归纳；边界看现场是否还连续（`M-02`）；直属事件，也可嵌套更细的场景（`container_evidence.CHILD_TYPES`） | 不是一个地点，地点是事件的 `world` 属性；不是剧本的场次（见 G-19）；不是章节、切片或提交批次（`M-06`） |
| 大事件 | **G-05** 部／卷内一个重要篇章：同一语境下连续的一大段进展，按披露顺序首尾相接；边界看阶段是否换了（`M-03`） | 不是范围容器（那是 G-06）；不是把若干事件打个包，阶段没换就不新建；不是「已完结」标记 |
| 主要故事 | **G-06** 一卷／一部的范围，条数不写死，可在进行中创建并持续修订（`M-04`）；完成度由程序从下级证据派生 | 不是完成标记，派生边界只表示最后证据的末端；不是故事发生时间；不是全书总汇 |
| 容器 | **G-07** 场景、大事件、主要故事三者的合称：归纳下级，证据与集合由下级派生；容器写入与下级同组的属性按 `M-16` 让位 | 不是任意有子项的节点；不是可以自己填 `quotes`／`closing_quote` 的对象（上层证据由程序派生，见提示词 v23） |

分层是硬的：主要故事直属大事件，大事件直属场景，跳级报 `STORYLINE_CHILD_TYPE`；每个活动事件都须经包含路径落在某个同语境的活动场景里（`EVENT_SCENE`），单事件也可自成一景。

## 2 属性与状态

| 概念 | 是什么（G-xx ＋ 规则引用） | 不是什么 / 易混 |
| --- | --- | --- |
| 属性（定义） | **G-08** 语义名称的状态变量形状：`value_type`、`cardinality`（one/many）、`symmetric`、`target_node_types`；先查已有定义再新增 | 不是给人物贴的标签或分类词，分类只是注释、不新造取值；不是自由文本备注；标量关系按对方分别维护（`M-09`） |
| 属性变更 | **G-09** `property_change`：只写在事件处，操作取 `set/add/remove/clear/unknown`，前三者带值、后两者不带（`M-07`）；作用域与持有人按 `M-08` | 不是对象字段的覆盖式改写；没有 `valid_from`／`valid_to`；不是一次覆盖整组状态 |
| 世界状态 | **G-10** 某个事件点上「节点 + 有效属性」的快照，由折叠变更算出：一次只折一组（主体、属性、语境、作用域、持有人），按事件顺序、同事件按 `sequence`（`M-10`）；读某点得到截至该点的状态（`M-11`） | 不是一条记录，也不单独存表，工程只存变更；不是最后一条记录（`M-10`）；不是全篇终态；清除与遗漏都不等于未知 |
| 判重：容器属性让位 | **G-11** 容器要写的属性若与某个下属事件同组（主体除外其余全同），以事件记录为准，容器写入被丢弃并回一条 `info`（`M-16`，码 `CONTAINER_PROPERTY_DEDUP` 附 `duplicate_of`） | 不是「容器不许有属性」；不是按名称相似度合并；不删已有记录 |
| 归纳派生 | **G-12** 容器的证据与阅读起点、完成边界、人物与地点集合，都由程序从下级算出（`M-04`）；进展属性记在下一级容器上，写到更上层被跳过 | 不是模型填 `quotes` 的替代写法；不是缓存；派生值不当事实直接改 |

两条机制的分界一句话：`storyline_progress`／`big_event_progress` 是**记录在下一级容器上、代表上级进展的属性**（写更上层被跳过，结果里 `skipped` 附原因）；T/B 自身能写的是**不来自下级事件的其他状态**，同一属性若下级事件已有则按 `M-16` 让位。

归纳派生与显式写入的分界也只有一条：这条事实有自己的事件与引文，就写成事件处的属性变更（G-09）；只是把下级的结论抬到上层，就由程序派生（G-12），不补一条等价记录。

## 3 语境、作用域与持有者

| 概念 | 是什么（G-xx ＋ 规则引用） | 不是什么 / 易混 |
| --- | --- | --- |
| 语境 | **G-13** 节点与属性所属的讲述语境：`canon`（正篇，默认）、`branch`、`hypothesis`、`viewpoint`（人物观点，带持有人）；折叠按「主体、属性、语境、作用域、持有人」分组（MODEL §1，折叠与冲突见 `M-10`） | 不是作用域（见 G-14）；不是时间线；不是模型的上下文窗口 |
| 作用域 | **G-14** 一条取值关于什么：`world` 客观世界、`cognition` 人物所知所信、`claim` 言说主张（`M-08`） | 不是语境；不是可信度评分；不是镜头视点；后两者不覆盖 `world` 的取值（`M-08`） |
| 持有者 | **G-15** `cognition`／`claim` 必须标明的认知者或说话人，取值是人物节点（`M-08`） | 不是物品持有者，那是 `world` 的「持有者」属性、缺失报 `ITEM_HOLDER_REQUIRED`；不是 `viewpoint` 语境的持有人 |
| 事件点 | **G-16** 读状态时给定的某个事件，可带事件内 `sequence`，读工具以 `cut` 传入；状态与派生值都截至该点（`M-11`） | 不是「最新状态」；不是原文切片端点，先后由 G-01 给；不是故事时间里的时间戳 |

`viewpoint` 语境的持有人和 `cognition` 的持有者是两件事：前者让整个语境的节点都从某人的角度讲，后者只管一条取值是谁心里的事。同一条事实换作用域或换持有人就是另一条记录，不能互相顶替。

## 4 提取层与剧本层

| 概念 | 是什么（G-xx ＋ 来源） | 不是什么 / 易混 |
| --- | --- | --- |
| 提取层 | **G-17** 从原文提取出的图：五层节点、人物／地点／物品、属性定义与属性变更；每条事实的引文逐字命中原文（`M-12`）。来源：MODEL 数据流与 `submit_extraction` | 不是剧本；不是资料卡；不是改写后的剧情 |
| 剧本层 | **G-18** 「剧本 → 段落 → 场次 → 正文块」这套写作对象，配一条本剧本独立事件线。来源：`AGENT_API.md` 与工具 schema（`submit_scene_table`、`submit_script_unit`） | 不是提取层的下游只读视图；不是原文的另一种排版 |
| 剧本场次 | **G-19** 场次（`script_unit`，`kind=scene`）是剧本里可独立写作与提交的演出单元：一份场表字段 `plan` 加一串正文块，可被镜头引用。来源：`AGENT_API.md` 与上面两个工具的 schema（场次＝unit、正文块＝block、场表＝plan） | 不是场景（见 G-04）；不是一次剪辑；不是原文的一段 |
| 本剧本独立事件线 | **G-20** 每个剧本自己的本地事件线，是源时间线的副本，决定本剧本还采用哪些事件。来源：`screenplay.timeline_id` 与 `script_timelines.source_timeline_id`，schema 里称「剧本独立改编时间线」 | 不是原文时间线；不是整部作品的故事时间 |
| 粒度 | **G-21** 工程设置 `standard`（阅读梳理）或 `fine`（默认精细），决定事件切多细。来源：`extraction_granularity` 与 `granularity_standard`／`granularity_fine` 两条提示词 | 不是场次数量；不是动作开关，两档都不默认提取动作（`M-05`） |

两层不互相写回：场次与正文块不进提取层的节点树，提取层的事实也不因剧本改写而变化（MODEL 数据流把场表与正文列为可选消费层）。剧本场次里的对白与动作属于剧本内容，不自动变成原文事实。

## 5 一个例子：同一段原文的「场景」与「场次」

> 原文（`examples/extraction_consistency_story.txt`）：「何雯接过钥匙……两人一前一后往东街走。街上刚下过雨，卖汤饼的摊子摆到了檐下……到了东街的旧楼，何雯在门口站了一会儿才上楼。」

- 按场景判（`M-02`，现场还连续吗）：西站门口（等人、交接钥匙）／东街街上（往东街走、雨里摆摊）／旧楼门前（到门口、上楼前）是三个现场，三个场景。
- 按场次判（一次可拍的时空单元）：西站门口一场，东街街上到旧楼门前合成一场——人物连续行走，一个移动镜头就能交代，不必跟着换街拆。
- 差别只在判据：场景问「现场是否还连续」，场次问「这一场怎么拍、写到哪一步」。
- 反向也一样：「钥匙我先拿着。」何雯从窗口往下说……林舟在楼下点点头，是同一个现场、时间连续的**一个**场景；剧本却常拆成 `INT` 三楼空屋与 `EXT` 旧楼楼下两场，内外景与反应镜头不同。

所以场景是提取层的叙事归纳，场次是剧本层的摄制与写作单元，两边边界可以不同，谁都不必服从谁。**此例照判据手工划分，不是某次模型运行的结果。**

三处措辞依据：

1. **世界状态**按 MODEL §1 的定义写：它是事件点上的快照，但由折叠变更得到、不单独存表，因此同时写了「是快照」与「不是一条记录」，与 `M-10`、`M-11` 一致。
2. **要素／标签**不是代码术语，最接近的是属性的 `category` 注释与剧本外的制作元素（`element`）；本表只保留否定面，没有新造词。
3. **G-07、G-18、G-19、G-20** 四个词在 v23 与 MODEL 里没有原词，改为引用 `AGENT_API.md` 与工具 schema 的现行叫法（场次＝`script_unit`、正文块＝`block`、场表＝`plan`、独立事件线＝`timeline_id`），并在词条内注明来源。
