# 画格 场内调度与关键帧重构方案

状态：设计方案，尚未实施。依据本轮讨论及当前代码只读审查制定。

## 目标与基本定义

以“表达什么、场内怎样发生、摄影机怎样观看、具体时刻怎样呈现”分别组织工作。推荐顺序为：

**画格意图 → 本场元素时空预演 → 镜头选择动作区间 → 机位与镜头语言 → 关键帧 → 剪辑预演与迭代。**

这是工作建议，不是阶段权限、强制向导或审批流程。用户和助手可从任意环节进入，通过 UI、对话、CLI 或 MCP 阅读及修改当前工程资料；允许先画、先调度、先排镜或回头修改。

| 名称 | 业务职责 | 不能据此声称完成的工作 |
|---|---|---|
| 意图画格 | 表达镜头主要视觉与叙事意图，包括观看重点、代表性动作、构图、空间及大致光照 | 不自动证明动作、机位和连续性已经落实 |
| 场内调度 | 描述同一连续性情境中元素的位置、朝向、姿态、视线、接触、状态及其随时间的变化 | 不等同于最终镜头取景或逐帧动画 |
| 机位与镜头语言 | 选择观看的动作区间，落实摄影机位置、方向、视野、运动和揭露方式 | 不替代人物动作设计 |
| 关键状态帧 | 在明确动作时刻与镜头取景下落实人物、物品、摄影机和必要光照状态，是关键帧的业务依据 | 不因存在一张图片而自动成立，也不负责补齐全部中间动作 |
| 关键帧图 | 表现关键状态帧的图像，可由合适画格复用或重新生成 | 不替代可编辑的状态与调度数据 |
| 播放图像点 | 指定某张图从镜内何时开始显示，保持到下一图像点，用于静态预演 | 不是动作或摄影机关键点，不证明动态连续性 |

画格可以提供动作意图，关键帧可以保留原图。二者的区别在用途和依据，不在画得精细与否。同一画格可派生零个、一个或多个关键状态帧；一个关键状态帧可以引用多个画格的意图，但只选择其实际采用的图像。

界面中仍以“关键帧”作为一个工作对象呈现状态与对应图像，不让用户维护两套平行流程。内部将状态依据和图像候选分开，是为了允许先设计动作、后出图，以及准确追踪变化。

## 总体素描与光照约定

软件内置默认采用描述型简洁线描：少量清楚轮廓与结构线、简单形体、充分留白。灰面仅用于表达必要的体积、局部背光、遮挡、接触暗部和投影；避免密集排线、纸纹、满幅灰调及精细材质渲染。

**简洁不能删除场景大致光照。** 应能理解主要光从哪里来、主体哪一侧受光或背光、必要投影指向哪里，以及整体明暗倾向。软光和高调场景不强加硬影，物体固有深浅不代替照明。简彩只增加必要的清淡色块，不破坏线条、形体和既定光照关系。

这项是软件总体默认，工程可明确覆盖。分镜画格和素描关键帧共用当前 `sketch_style`。实际运行不依赖用户下载目录中的指南文件。正式项目风格化是后续可选工作，不自动取代素描预演。

## 现有实现与重构边界

当前已有 `board.objects`、对象动作关键点、`markers`、镜头摄影机轨、2.5D 投影、画格候选与采用、图像生成依据和失效提示，可继续使用其已有能力。

当前主要问题：

- `shot.panels` 的画格必须拥有落在镜头时长内的 `offset_ms`，把正常意图规划误作必须先完成计时。
- 旧 `keyframes` 主要保存图片与镜内时间；“采用画格为编排关键帧”实际执行图片绑定，缺少关键状态的职责。
- 共同动作轴依赖镜头的 `action_start_ms + local_ms`，缺乏可独立预演、可明确区分时空跳跃的连续性情境。
- 没有镜头时，现有剪辑预览不提供完整场面对象预演，无法自然支持先调度、后机位。
- 图片采用数量、静帧覆盖、调度完整性和动态产出容易被合称为“完成”。

本次直接设计新合同，不增加旧字段兼容、隐式迁移、双写或重定向。实施前按新合同准备隔离测试数据，不自动重写当前用户工程。现有 47 镜、51 格的真实产物继续如实称为静态画格及播放编排，不凭新名称重新认定为动态调度完成。

## 数据职责

下列名称为目标合同建议名，实施时由 Operations 发布具体字段与可修范围。ID、排序键、派生时间、依据摘要等机械字段由程序生成；模型只提交实际设计内容及已读取的业务引用。

### 意图画格

画格按场保存，通常归属于一个镜头；允许暂不分配镜头，以支持缩略草稿和重新分镜。一个画格不默认被多个镜头共同拥有，避免一处修改意外改写多个镜头。

最少内容：

- 可读 ID、独立排序键、可选镜头引用。
- 画格意图、观看重点、代表性动作阶段、必须保留与可概括的关系。
- 可选情境及动作时刻引用；没有精确时间是合法规划状态。
- 光照意图、可见元素引用、候选图与采用关系。

画格排序不由 ID 或时间决定。画格可标记“动作前”“接触时”“结果显露”等语义时刻，之后再关联命名时刻；不得为了保存而伪填 0ms。没有精确时间不进入待修暂存。

现有镜头资产元素表继续作为对象需求和资产选择入口，不另建重复资产清单。画格只选择本格涉及的元素。待确定资产不阻止意图规划；明确绑定时仍检查真实对象、类别和引用。

### 连续性情境与本场对象

每场可拥有一个或多个连续性情境。一个情境提供共用空间、局部动作时钟、对象初态、命名时刻及大致光照；通常先用一个，实际时空跳跃或独立表演需要时再增加。

对象实例表示“本场的这个人物或物件”，资产表示其外观。同一人物换形象不重建人物实例，同名不同物件不自动合并。资产尚未确定时允许使用有名称的简化占位对象。

每个情境明确对象是否出现及初始状态。动作轨按情境记录对象位置、朝向、姿态说明、视线目标、接触或支撑关系及必要状态变化。已有位置、父子关系、`hold/linear` 和命名时刻机制可复用；姿态、视线、接触增加明确的可引用结构，不全部塞入无法定位的自由 JSON。

情境统一保存坐标方向、空间范围和相对尺度，并支持明确的长度单位。同一情境不能为每个镜头重新设定对象坐标；取景差异由摄影机表达。统一合同保存三维位置、朝向及必要姿态，后端适配器负责坐标轴、单位和摄影机参数转换，不要求完整物理模拟；缩放工作区只是改变观察方式。2.5D 视图只能作为能力受限的显示方式，不能约束三维业务数据。

只对实际使用的关系要求必要内容，不要求每个对象填写完整骨骼或每个关节坐标。模型判断动作边界和设计合理性，程序不以题材词表或固定动作数量切分。

对象实例可在多个情境出现，但状态轨归各自情境；新的情境明确初态。跨情境不自动插值、不自动补路程、不按同名复制身份或猜测状态延续。

### 大致光照

光照归连续性情境，可引用场内灯具，也可记录画外光。按需要保存世界空间的主要光向或光源位置、软硬、环境亮度及补充说明；发生明确变化时关联命名时刻。

镜头改变机位后，程序据此给出相对观察方向的近似光向，模型在草图上落实主要受光、背光和必要投影。当前 2.5D 不承诺真实表面法线、复杂遮挡或物理光照；无法计算的内容明确作为设计说明，不伪称已由几何验证。

### 镜头与三种时间

| 时间 | 含义 | 归属 |
|---|---|---|
| 情境动作时间 | 本情境中元素的共同变化 | 情境 |
| 镜内时间 | 本镜开始后的局部播放位置 | 镜头 |
| 剪辑时间 | 各镜排列后的播放位置 | 编排派生 |

镜头引用情境、动作起点、意图画格、观看重点和摄影机设计。初期继续采用 `action_ms = action_start_ms + local_ms` 的 1:1 映射，避免第一轮重构引入复杂变速系统。保持状态可通过动作轨 `hold` 表达。

相邻镜头可以选择不相邻、重叠甚至更早的动作区间，也可切换情境。剪切立即切换取样依据，不把剪辑间隙计算成人物必须走过的时间。省略、重看、时空跳跃及表达性处理可记录切换意图，程序不能仅因数值不连续而拒绝。

镜内确需时间断裂时，应明确设计新的片段或镜头，不以隐藏的坐标瞬移代替。变速与分段映射放在后续扩展，不作为首期前置。

尚未确定的镜头时长、机位和动作区间是合法草稿，可随时编辑。未计时镜头不能默认为零时长或被悄悄跳过后声称全场时长已确定；剪辑预览明确区分已排定片段与未定位内容。

### 关键状态帧与关键帧图

关键状态帧属于镜头，绑定镜内时刻或命名时刻；情境及动作时刻由镜头映射派生。其依据包括：

- 关联画格的表达意图与必须保留项。
- 当时对象位置、朝向、姿态、视线、接触和状态。
- 摄影机位置、方向、视野及构图要求。
- 当时大致光照和相关资产状态。

保存关键状态帧不自动生成图片，也不自动画完中间动作。允许先记录不完整设计，明确显示缺少哪些依据。执行“按调度生成关键帧图”时才检查所需机位和状态是否具备；缺少依据要说明，不能静默改用普通意图格生成并标为动态完成。

“引用画格作为依据”“复用画格图片”“生成关键帧图”和“加入静帧播放”是四个明确动作。复用已有图片时仍保留关键状态与依据；若图与状态不符，记录问题并调整状态或重画，不能靠更名解决。

结构合法、依据当前、图像存在、语义问题四项分别反馈。程序只验证可确定计算的部分，姿态自然性、动作表达和复杂接触由助手或用户判断；不增加人工接受、逐帧审批或阶段解锁工作台。

### 播放图像点

播放图像点只保存镜内时间和实际图像引用，可引用意图画格或关键帧图。保持到下一点的语义保留，但不得因此创建、推断或覆盖场内动作及摄影机状态。

未完成调度的画格仍可立即排成静态预演。起始图复用代表格是播放安排，不改写代表动作时刻，也不自动创建已经成立的关键状态帧。

## 交互设计

分镜稿模块负责镜头意图、画格、元素需求与静态预演；导演台负责场内时空设计、逐镜观察、关键状态及动态预演。两者共享数据引用，不复制两套镜头或正文。

导演台建议布局：

- 左侧保留场与镜头列表，镜头显示关联画格、动作区间及缺项摘要。
- 中央“场内预演”支持俯视或自由观察，在没有镜头摄影机时也能播放情境动作。
- 并列“镜头取景”显示当前镜头摄影机视图；未设置时直接显示未设置，不借自由观察视角伪装成正式机位。
- 下方分别显示情境动作轨与剪辑镜头轨，支持跟随映射、独立查看、缩放和命名时刻跳转。
- 侧栏编辑选中对象、姿态与关系、光照、摄影机或关键状态；意图画格随时可对照。

自由观察角度、缩放、视图联动和选区只是界面状态，不写入摄影机设计。对象“编辑初态”和“记录当前动作点”明确分开；未开启记录不自动产生动作关键点。

替换“采用画格为编排关键帧”按钮：

1. 加入静帧预演：只创建播放图像点。
2. 用作关键状态依据：关联画格并按当前调度与机位采样状态。
3. 复用图片：明确将已有图片关联到关键状态，并反馈依据或语义问题。
4. 生成关键帧图：依实际状态、光照和资产绘制候选，再选择采用图。

完成情况由程序分别统计：有图画格、静帧覆盖镜头、已有调度的情境、已设置机位的镜头、关键状态及图像覆盖、待更新依据、可用动态片段。界面不使用一个“关键帧完成”覆盖所有状态。助手任务结束的入库汇总继续由程序输出。

## 可切换的三维预演后端

三维预演采用后端适配架构，不将工程数据绑定到某个引擎。首期采用 Three.js 作为轻量级实时预演后端，后续按实际调度需求接入并允许切换 Godot。不采用 Blender，不建设其制作、离线采样或渲染接入。Babylon.js、Panda3D 不列入当前实施范围。

### 统一数据与职责边界

- Operations 管理唯一的情境、对象、动作、姿态、接触、光照、摄影机及关键状态事实；后端仅接收指定修订的数据与派生采样，不拥有第二套正式工程。
- 统一定义坐标轴、单位、旋转表示、时间单位、摄影机投影和视野约定。适配器做明确转换；中间资源可使用 glTF 等交换格式，但不以某个引擎场景文件代替业务合同，也不假定交换格式能承载全部约束。
- 后端交互返回对象引用、修改意图及原修订，由宿主通过 Operations 暂存、检查和提交。拖动期间可有临时画面预览；不得绕过 Operations 将后端内存或场景文件直接写成正式事实。
- 确定性动作取样、时间映射和剪辑切换由公共业务层负责；后端按指定时间呈现。引擎动画、IK 或物理解算只提供明确标识的预览结果或候选烘焙数据，不静默改写轨道。物理模拟必须声明是否支持可重复跳时，不能将顺播模拟冒充任意时刻的确定性采样。
- 后端专属资源、缓存和制作文件与正式数据分离，按可读后端名和实际版本记录来源；扩展参数有命名空间。可编辑成果回传时须显式转换、检查并提交，不能将不可解析的专属文件伪装成通用可编辑调度。

### 后端合同与能力发现

公共接口覆盖发现及健康检查、创建与关闭预演会话、加载指定修订、增量同步、按时间采样、更新观察视角、拾取与编辑意图、截图及渲染任务。任务携带会话和修订依据，过期响应不得覆盖当前画面或工程；关闭、取消、断连及超时均有明确结果。

每个后端发布能力及限制，至少区分：

| 能力 | 需要说明的差异 |
|---|---|
| 实时交互 | 是否支持内嵌、独立窗口、拾取、拖动及多个视图 |
| 几何与姿态 | 简化对象、骨骼、IK、视线、接触约束的实际支持范围 |
| 摄影机与光照 | 投影、镜头参数、阴影和近似照明能力 |
| 时间与动画 | 任意跳时、动画混合、模拟预热及烘焙要求 |
| 图像与交付 | 截图、素描显示、离线帧序列和视频输出能力 |
| 资源交换 | 支持格式、丢失字段和专属资源依赖 |

缺少某项能力时，保留原数据并明确显示“当前后端不支持”；不能丢字段、自动简化后保存，或改用其他后端而不提示。近似接触、姿态或光照须标明近似程度，不因后端宣称支持 IK 就认定动作自然或接触正确。不同后端的画面不要求像素一致，业务时间、身份、位置及摄影机转换必须一致。

### 设置与切换交互

工程设置保存首选预演后端及可共享的显示设置；安装路径、设备和本机服务地址等环境配置保存在设备设置，不把密钥或本机绝对路径写进共享工程约定。导演台提供当前后端选择、状态与能力说明，UI、CLI、MCP 和助手共用同一发现及选择能力。

切换前先收束尚未提交的编辑，再以同一工程修订、情境、播放头、选区和可转换的观察视角创建新会话。切换不改变动作、机位、画格、资产或关键状态，不自动重新生成图片；无法转换的工作区视角可重置并提示，正式摄影机设计不得因此改变。后端未安装或启动失败时保留工程与选择依据，显示具体原因和可用选项，不自动安装或静默切换。

首期截图和预演输出由 Three.js 后端提供；后续 Godot 沿用同一产物合同，不另建离线渲染后端选择流程。截图和渲染产物记录实际后端、版本、工程依据、相关资源及输出设置；仅切换观察后端不使意图画格失效，而依赖特定渲染设置的产物应能提示差异或待更新。

### 实施与验证范围

先落实中立数据、采样及后端合同，再实现 Three.js：简化人物与几何场景、俯视与自由观察、镜头取景、对象拾取与移动、近似光照及按时间采样。姿态与接触按实际能力标明，不把简单代理表现当作完整骨骼或物理解算。首期不实现 Godot 适配器，不为未来切换重写一套动画系统；通过中立合同、坐标转换和采样测试约束引擎耦合。后续需要更完整的骨骼、动作组合或约束时接入 Godot，并进行真实双后端切换验证。

首期最小验证覆盖同一两人交接情境的统一身份、坐标、时间、机位及光向到 Three.js 的转换；Godot 接入时再验证两个实际后端间的一致性，不以模拟适配器声称双后端已完成。独立视图可观察不同时间且互不改写；切换前后正式内容一致；编辑仍经 Operations；不支持能力不丢数据；断连、过期响应和取消不产生错误写入。模拟或插件结果另测，不用截图相似替代合同验证。

## Operations 与助手合同

建议按能力拆分统一入口，具体命名以正式工具目录为准：

| 能力 | 入口建议 | 职责 |
|---|---|---|
| 意图规划 | `read_storyboard_intents` / `submit_storyboard_intents` | 未定时长的画格与视觉关系 |
| 场内设计 | `read_scene_staging` / `submit_scene_staging` | 情境、对象初态、动作与大致光照 |
| 场内预演 | `preview_scene_staging(context_id,time_ms)` | 不依赖已排镜头，纯读取派生状态 |
| 镜头取景 | 复用镜头编辑并扩展情境引用 | 动作起点、画格关联、摄影机与镜头语言 |
| 关键状态 | `sample_shot_state` / `submit_shot_key_states` | 程序采样机械状态，模型补充表达及姿态要求 |
| 静帧编排 | 独立图像点编辑入口 | 图片与播放位置，不改调度 |
| 生成与复核 | 复用生成、检查及导出能力 | 记录真实输入和来源，区分当前、变化及不可解析 |

模型工具常驻只保留发现和必要通用能力，细分合同按需加载。工具可随时使用，固定任务仅防止越出本次明确选择的对象范围，不设置只能进入某个制作阶段的全局写入白名单。

读取支持选择情境、对象、时段及必要字段；预览返回当时的派生状态，不例行回传全场所有候选图和历史任务文本。公共参数、内容修补及错误合同统一发布，避免 UI、CLI、MCP 或工具家族重复定义。

业务内容统一 Operations 暂存、静态检查与局部修补。诊断包含原始字段路径、对象、情境及具体时间；合法草稿的未定项不伪装成错误。并发过期、权限、固定目标、文件、网络和未知错误硬拒，不包装成待修内容。

确定性状态采样和预览为只读，不分配正式对象、不写修订。删除、移动、复制、图片采用、显式图像生成、导入导出等即时命令保留原子语义，不藏在通用 patch 中执行。图片生成任务开始与写入时均核对实际依据；失败保留已有材料，不自动重试或回退几何图。

当前开发阶段由 ChatGPT 提供实际图像，软件内助手负责全部工程操作。外部仅接收出图需求、提供图片，不直接写数据库或调用业务修改来替助手补结果。未来本机或远程服务沿用同一输入与来源合同。

出图需求清单由程序根据画格或关键状态、素描约定、光照和实际资产引用生成，机械字段包括可读请求编号、目标引用、依据版本及真实参考文件路径。助手补充画面表达要求，避免手写整场派生状态、摘要或大批文件路径。外部回传实际图像后，由软件内助手调用导入、候选采用及关联操作；程序核对目标和生成时依据。状态变化后的图像可保留为过期候选，但不得静默作为当前关键状态的合格产物。

## 依赖变化与检查

采用实际引用及取样区间追踪依赖；首期不能精确判断时允许明确标注保守影响范围，不伪装像素或语义验证。

| 改动 | 主要影响 |
|---|---|
| 画格意图 | 引用该格的关键状态及其图像 |
| 对象动作、姿态、接触 | 取用相应情境和动作区间的镜头及关键状态 |
| 情境初态或光照 | 该情境中相关镜头、状态和图像 |
| 摄影机或镜头映射 | 本镜相关状态及图像；不改共用动作 |
| 资产形象 | 实际引用该资产的图像；不重建人物实例或改动作 |
| 镜头调序 | 剪辑位置及衔接提示；不移动动作轨 |
| 播放图像点 | 静态预演换图位置；不改变动作设计 |
| 总体或工程素描风格 | 素描产物待复核，不自动重画 |

结构检查包括引用归属、循环、有限数值、时间类型、已定位内容的区间、同轨冲突、实际媒体存在与修订。正常跳切不报动作不连续硬错误。穿帮、意图偏离、不自然表演和复杂接触作为语义反馈，不用硬编码词表或几何近似静默裁决。

## 分期实施与验收

| 期次 | 可交付范围 | 最小验收 |
|---|---|---|
| 一 定义与静帧分离 | 新画格合同、可不定时长、独立播放图像点、真实完成状态与按钮命名 | 无机位画格可保存与静态播放，但不会产生关键状态或动态完成标记 |
| 二 独立场内预演 | 情境、对象身份与资产分离、初态、动作轨、接触/视线、大致光照、独立播放头、中立后端合同及 Three.js 轻量预演 | 无镜头时仍可预演接近—接触—离开；动作和光照保存重开一致，待确定资产可用简化对象 |
| 三 镜头观察与关键状态 | 情境映射、机位轨、状态采样、意图引用、关键帧图与静帧编排分离 | 两镜重看同一动作，另一镜跳到新情境；各自机位正确，不自动补运动；复用图片不替代状态 |
| 四 生成与联播交付 | 统一素描输入、局部失效、临时声音、真实来源与分层导出 | 只改一个动作或机位能指出影响范围；静态预演、调度预演、动态视频明确区分，错误不自动重生 |

第一期即删除旧概念耦合，不同时维护“旧关键帧”与“新关键帧”两套写入语义。后续按能力补齐，不以隐藏默认值假装未完成部分已完成。

贯穿样本使用最小普通情境：两个人、一件可交接物、一处通道。先设计接近、停顿、交接、离开；用一个镜头看接近，另一机位重看交接，再以跳切表现离开后的情境。核对物品归属、手物接触、视线、光向、剪辑取样和关键状态；不依赖某种题材或固定事件数量。

每期运行必要自动化检查，并按影响范围做最小真实兼容模型验收；图像阶段使用实际生成结果，明确区分模型判断与程序派生。采用隔离库和独立报告，保存原始输出、版本、配置摘要、用量、诊断和真实写入；失败不手工补成成功，不自动追加请求。当前仅编写方案文档，不触发真实模型请求。
