# 数据模型

> 本文只讲存储：schema 11 的表、编号、包含关系与事务怎么落库。提取规则（属性状态推导、事件地点／持有者必填、逐字证据、五层边界、诊断码）只看[提取任务规范](../extraction/SPEC.md)，本文只引用编号，不复述判断标准。

工程存储使用 schema 11。节点保存当前对象，属性保存事件处的建立、变更和失效操作；读取不重放修订日志。

## 身份、证据与阅读位置

节点包括人物、群体、物品、地点、主要故事、大事件、场景、事件、动作和其他。每个节点有稳定的类型编号、名称、别名、语境、原文证据和首次披露位置；节点改名不改变身份。节点没有修订旧版本。

阅读位置由原文来源顺序与 Unicode 字符偏移组成：`{source_id, start}`，可附 `event_id`。偏移不是 UTF-16 单元，结束位置不包含在范围内。来源顺序保存在 `source_order`，不能用编号、录入时间或文件名代替。先后的判据（含「补录早先事实不改变最新状态」）见[提取任务规范](../extraction/SPEC.md) §4 `M-06`、§5 `I-32`。

动作使用 `action` 类型与 `A` 编号，低于事件。阅读层级为主要故事（storyline/T）→ 大事件（big_event/B）→ 场景（scene/S）→ 事件（event/E）→ 动作（action/A）；直属关系、动作该挂哪一层、跨层先后怎么判，见[提取任务规范](../extraction/SPEC.md) §5 `I-21`、`I-23` 与 §4 `M-05`、`M-06`。

原文与附件保持独立存放。精确证据使用来源、起止位置和逐字引文；存储保留复核补充的多处披露证据与历史证据，不设引文数量上限，也不删改既有结果。一条引文够不够、同名或位置相近能不能证明同一次事件，判据见[提取任务规范](../extraction/SPEC.md) §3 `E-09`、§4 `M-13`、`M-15`。

场景、大事件、主要故事不落自身 `quotes`／`closing_quote`：模型提交名称及直属层级关系（`children` 或子项父级引用），程序逐层汇集已验证下级的精确证据，按正式来源顺序和 Unicode 坐标派生阅读起点。已有下级的证据可跨原文来源或提交批次复用，不要求在当前范围重新抄写。容器引文被谁丢弃、派生失败怎么报，见[提取任务规范](../extraction/SPEC.md) §3 `E-10`、§5 `I-10`。

## 当前节点与包含关系

`objects` 每个 ID 只有一行当前对象。更新直接修改该行，不保存对象旧副本。主要故事以 `events` 包含大事件，大事件包含场景，场景包含事件或嵌套场景，事件包含动作。包含关系不得成环、每个活动事件必须经包含路径属于同语境的活动场景，判据与诊断码见[提取任务规范](../extraction/SPEC.md) §5 `I-22`、`I-24`。

主要故事表示一卷／一部的范围，可在进行中创建；T 尚未建立时累积大事件、场景和事件，大事件可暂不归主要故事。`completion: {source_id,start}` 由程序从下级已验证证据按正式来源顺序与 Unicode 位置派生，取最后证据末端为半开右界，不用模型填写的 `closing_quote`（判据见[提取任务规范](../extraction/SPEC.md) §4 `M-04`、§5 `I-33`）。容器可用 `children` 引用已有直属子项，因此总结主要故事只需关联已有大事件，不需重列整篇节点与旧引文。

主要故事和大事件都只有一个清晰概括的 `name`，不存暂称／正式名双轨，也不添加暂称后缀。大事件同语境依原文披露位置形成 `[start,next.start)` 连续阅读区间；末个大事件若已归入完成的主要故事，以其 `completion` 封口，否则 `end=null`。主要故事范围起点来自成员大事件，终点为下级已验证证据派生的闭合右界；这些都是阅读区间，不是故事发生时间。

大事件与主要故事的「进展」就是它**当前生效的名字**：名字是一条 `名称` 属性，改名写一条新的 `名称`，旧名随 `set` 失效；`name` 只是建节点时的初始值（`U-13`，见[提取任务规范](../extraction/SPEC.md) §0.1）。所以没有「进展属性」这一族，容器也不从子级汇总出第三份名字。

事件物理合并重写所有有类型的引用，将证据和子项并入保留对象，删除被合并对象；不保留合并重定向链。字符串正文不因恰好等于某节点 ID 而被改写。

## 属性事件变更

存储只有 `property_definition` 与 `property_change` 两类记录：没有 `valid_from`／`valid_to`／有效期／`expirations` 字段，状态不落库、读取时按正式来源与事件位置、同事件 `sequence` 折叠。记录字段、五个操作码的语义、序号由谁生成、同事件同序号冲突怎么报，全部在[属性状态合同](../extraction/SPEC.md#属性状态合同schema-11)（`I-19`–`I-31`）；本节不重复那份判据。

对称关系由定义的 `symmetric` 严格布尔字段表达；不按名称词表猜测，不补写无证据的反向变更。作用域、持有人和语境分别推导。

## 修订与回退

`revision` 只用于并发检查。轻量动作审计记录动作、原因及 ID／数量摘要，不保存整份节点或数据库快照；没有可回放的修订对象表。原始模型输出和任务诊断独立保存，不能当作当前事实读取。

回退按阅读时间点执行，规则见[提取任务规范](../extraction/SPEC.md) §5 `I-29`；落地方式：先预览，再在同一事务中删除该点之后的节点与变更、清理引用，再按剩余变更推导状态。边界点本身保留。回退不恢复节点的旧名称或旧编辑副本，因为这些版本不存储。若删除将破坏场景、引用、持有者等静态约束，整个事务拒绝，不能伪造事实补齐。

## 校验与旧工程

UI、CLI 与 agent 均通过 `Operations` 写入。结构、引用、逐字证据、包含关系、值类型、事件顺序、状态冲突与持有者等静态检查在提交事务前执行；独立静态检查页可手动检查和跳转问题。

仅支持当前 schema 11；旧版工程直接拒绝打开，不提供兼容读写、转换或迁移入口，原文件不改动。

## 工程提取粒度

工程设置保存 `extraction_granularity`：`standard`（阅读梳理）或 `fine`（默认精细，额外细查非关键及无名人物、具体地点）。两档只决定事件切多细；场景／事件／动作的定义、事件边界怎么判、章节与批次不作边界、`participants` 与事件地点的必填要求，都在[提取任务规范](../extraction/SPEC.md) §3（`E-05`、`E-08`、`E-17`、`E-19`、`E-20`）、§4（`M-01`–`M-06`）与 §7 的两条粒度提示词里；本文不复述判据，也不再另举边界示例。

两档默认都不提取动作。在事件节点编辑器点击“动作提取”时，向当前统一助手会话提交一个带父事件 ID 的任务，读取原文及已有动作后按需新增/复用动作；不另启提取进程，也不重提整章。常规事件粒度与动作展开独立。

模型配置复用项目现有 Provider 设置，粒度随工程保存。新任务读取当前设置，改变设置不自动重提既有数据。

## 稳定编号与直接批写

原文使用 `SRC1`、`SRC2`，属性变更使用 `PC1`、`PC2`，切片使用 `SRC1-SL1` 等真实存储编号，不维护另一套短名映射。编号由程序分配；属性变更计数器与事实同事务更新，删除后不复用。节点仍使用P/E/A等类型编号，属性定义继续用语义名称。项目/聊天/SDK调用等内部身份不进入普通事实工具参数；内容hash仅用于程序校验。

取值去重使用主体、属性、类型化值、作用域、认知持有人、披露位置、原文证据和适用事件等完整字段，不以截断hash充当去重规则。不同作用域/持有人或不同披露位置的记录分别保留；相同事实的分类等注释更正不新造取值。

自动提取和通用修改不再使用暂存候选表或propose/accept链。一次只读事务捕获同版对象、属性、原文和修订；宿主完成一次准备与静态校验，预先计算并序列化变化行。写事务仅核对修订、提交差异行、推进编号与写操作摘要，失败全部回滚。仍保留一轮完整静态校验，并非全部计算只随增量增长。

单原文工具可省略source_id，多个原文须明确指定；批量引文定位一次读取原文并复用重复quote结果，输出原文坐标、准确性/截断诊断。规律章节由程序同事务扫描、校验并创建，不需要模型往返source_hash/plan_id。
