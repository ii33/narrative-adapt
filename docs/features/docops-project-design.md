# docops 工程组织设计

> 状态：工程设计稿，`narrative-docops` 仓库尚未创建（本文档不描述现有行为）

本文是概念设计稿的**工程篇**：只讲仓库怎么摆、配置怎么写、命令怎么排、测试怎么分层、按什么顺序落地。概念、状态机、签名与门禁规则一律以 [docops-traceability.md](docops-traceability.md) 为准，本文不重复定义；两者冲突时以概念稿为准，本文只补它没写的工程细节。

将来搬进独立仓库时，本文即该仓库的 `docs/DESIGN.md`。

## 1 仓库结构

```
narrative-docops/
  pyproject.toml
  docops.toml                 # 项目配置（§2），唯一与具体项目耦合的文件
  requirements/               # 需求分片（事实源）
    ext.yaml
    prop.yaml
  schemas/
    requirement.schema.json   # 条目字段的 JSON Schema
  src/docops/
    cli.py                    # 参数解析、退出码、--json 输出
    config.py                 # 读 docops.toml，补默认值并校验
    model.py                  # 条目模型、状态枚举、稳定序列化
    index.py                  # 加载分片，建 ID→条目与锚点→REQ 的索引
    hash.py                   # AST 规范化与摘要
    graph.py                  # 依赖图与反向传播
    signature.py              # 签名组合、比较、降级判断
    checks/
      __init__.py             # 检查注册表（名字、严重级、是否硬门禁）
      links.py                # 相对链接存活
      line_refs.py            # 行号引用
      symbols.py              # 文件.py::符号 是否存在
      codes.py                # 诊断码是否在源码里出现
      terms.py                # 术语词条能否落地
      retired.py              # 停用句式（含白名单上下文）
      gates.py                # 三条硬门禁与豁免过期
    render/
      markdown.py             # INDEX / DETAIL
      html.py                 # 单文件 HTML
      diff.py                 # fmt --check 的逐字节比对
    i18n/
      zh.py / en.py           # 固定键位的文案表
  tests/
    unit/ integration/ regression/ snapshot/
    fixtures/{basic,stale,ack-expired}/
  out/                        # 生成物（git 忽略）
  .docops-cache.json          # 缓存（git 忽略）
```

模块职责一句话：

| 模块 | 职责 |
| --- | --- |
| `cli` | 唯一入口：解析参数、调 `checks`／`render`、决定退出码与 `--json` 形状 |
| `config` | 把 `docops.toml` 变成带默认值的配置对象；缺项报错而不是猜 |
| `model` | 条目对象与状态枚举；序列化时键序固定 |
| `index` | 一次性加载全部分片，产出两向索引（ID→条目、锚点→REQ） |
| `hash` | 函数体 AST 规范化与摘要（概念稿 §5 的落地） |
| `graph` | 依赖图与反向传播、`--changed` 的命中计算 |
| `signature` | 组合 `(req, impl, tests, contracts)` 与比较、stale 判定 |
| `checks/*` | 每条检查一个模块，纯函数：输入快照与配置，输出问题列表 |
| `render/*` | 只把数据渲染成 Markdown／HTML，不判断对错 |
| `i18n` | 固定键位的文案，供 `render` 与 `cli` 取用 |

**分层铁律**：

- `checks/` 不得 import `render/` 与 `cli/`——检查只回答「有没有问题」，怎么展示是下游的事。
- `render/` 只消费 `model`／`index` 给的数据，不做任何判定（包括「这样写算不算过」）；否则同一规则会出现两份实现。
- `cli/` 是唯一入口：任何检查都不自己读 `sys.argv`，任何渲染都不自己决定输出路径。
- `i18n` 只提供字符串，不带逻辑；缺键直接报错，不做静默回退。

## 2 配置契约

`docops.toml` 是工具与具体项目之间**唯一**的耦合点。示例就是主项目的配置：

```toml
[project]
name = "narrative-adapt"
root = ".."                                  # 主项目根，只读
docs_glob = ["docs/**/*.md", "AGENTS.md", "README.md"]
source_glob = ["src/**/*.py"]
test_glob = ["tests/**/*.py"]

[ids]
prefix = "REQ"                               # 编号前缀，不是业务概念
domains = { EXT = "requirements/ext.yaml", PROP = "requirements/prop.yaml" }

[obligations]                                # 「文档必须给出的表格」这类义务
columns = ["ID", "不变量", "校验点", "诊断码", "覆盖测试"]
marker = "|"                                 # 以表格行计
required = ["校验点", "诊断码"]               # 缺列即红灯

[retired]                                    # 停用句式
phrases = [
  { old = "示例：某个已被替换的长句", why = "现行写法：替换后的短句" },
]
allow_context = ["场次", "script_unit"]       # 命中这些词的段落豁免（不许整篇豁免）

[gate]
hard = ["implemented_signature_match", "req_version_verified", "planned_no_anchors"]
exempt_max_days = 90
exit_on_warn = false                         # 黄灯默认不改变退出码

[render]
lang = "zh"
out = "out"
index = "INDEX.md"
detail = "DETAIL.md"
html = "report.html"
```

**复用前提**：上面每个值都是主项目的事实，工具侧**不得出现其中任何字面量**。判断方法很简单——在主项目名字全替换成 `acme` 的仓库里跑一遍，若报错信息里还出现 `docs/`、`REQ`、`INVARIANTS` 之类的词，就是硬编码漏出来了。检查项的集合也由配置决定：`checks` 按注册表运行，配置里关掉某一项，它就不跑，也不出现在报告里。

## 3 CLI 表面

| 命令 | 用途 | 退出码 | 写操作 | 需 `--allow-agent-write` |
| --- | --- | --- | --- | --- |
| `docops check` | 跑全部已启用的检查与门禁，输出问题列表 | 0 通过 / 1 红灯 / 2 用法或配置错 | 否 | 否 |
| `docops trace <ID>` | 打印单条目链路：`REQ → 编号前缀 → 义务项 → code → test` | 0 / 2（ID 不存在） | 否 | 否 |
| `docops report` | 生成 `INDEX`／`DETAIL`／HTML 到 `out/` | 0 / 2 | 是（只写 `out/`） | 否 |
| `docops req new` | 分配新 ID 并建条目骨架 | 0 / 2 | 是 | 是 |
| `docops req change` | 按 `--kind` 改条目（概念稿 §7 的门槛） | 0 / 1（门槛未过）/ 2 | 是 | 是 |
| `docops req verify` | 复核签字：写入新签名与 `verified` | 0 / 1（签名不匹配）/ 2 | 是 | 是 |
| `docops req backfill` | 反补录历史条目（`origin` 记为反补） | 0 / 2 | 是 | 是 |
| `docops fmt --check` | 比对 `out/` 与重新生成的字节 | 0 一致 / 1 有差异 / 2 | 否（可加 `--write` 重写 `out/`） | 否 |
| `docops sync` | 刷新主项目快照与缓存（§7） | 0 / 2 | 是（只写 `.snapshot/` 与缓存） | 否 |

约定：所有命令支持 `--json`，输出固定形状 `{ok, code, items, summary}`；`1` 只用于「检查不过」，`2` 只用于「工具没跑明白」（参数、配置、快照缺失），两者不混用——CI 才能区分「业务红」与「环境坏」。

## 4 数据与边界

- **事实源**：`requirements/*.yaml`，按功能域分片，单片 ≤200 条（概念稿 §10 的拆分规则）。工具不改写分片以外的东西。
- **生成物**：`out/INDEX.md`、`out/DETAIL.md`、`out/report.html`。每份首行固定：

  ```
  generated by docops <ver> · commit <rev> · sha256:<输入集合摘要>
  ```

  `commit` 是快照的提交号，`sha256` 是对「条目 + 配置 + 快照摘要」的稳定摘要——两者一起回答「这份报告基于哪一版事实」。
- **缓存**：`.docops-cache.json` 存 AST 摘要与依赖图，键含文件相对路径与规范化摘要；可随时删除，删了只重算。缓存不是事实源，任何结论都不得只存在于缓存里。
- **写入边界**：只写 docops 仓库内的 `requirements/`、`out/`、`.snapshot/`、`.docops-cache.json`。**主项目零写入**（见 §7）；只读快照也由工具自己拉取，不读主项目工作区。

## 5 测试策略

| 层 | 内容 | 判据 |
| --- | --- | --- |
| 单元 | AST 规范化（注释/格式/局部改名不变，控制流变必变）、签名组合、图传播与 `--changed` 命中 | 纯函数、无文件系统、无 fixture 仓库 |
| 集成 | 三个 fixture 仓库（`basic` 全绿、`stale` 含失效项、`ack-expired` 豁免过期）跑全命令 | golden 文件逐字节比对 |
| 回归 | 主项目 `docs/` 快照上，新工具与现有六项检查的结论逐条对比 | 零差异；出现差异必须能指到具体检查项 |
| 快照 | 生成物连续多次生成的字节一致性 | 连续 10 次逐字节一致（概念稿 §12 的门槛之一） |

补充两条：集成测试的 fixture 仓库**不复制主项目内容**（否则它变成第二份事实源），只放最小条目与几个假函数；回归测试消费的是 `git archive` 快照（§7），不是当前工作区，避免「本地改了没提交」污染对比。

## 6 里程碑 M0–M4

| 里程碑 | 内容 | 验收 |
| --- | --- | --- |
| **M0 骨架** | `cli`／`config`／`model`／`index`／`hash` 与单元测试；`check` 尚不含具体检查 | 空仓库 `check` 返回 0；`--json` 结构与文档一致；配置缺项报 `2` 而不是猜 |
| **M1 等价** | 实现六项文档检查（链接、行号、符号、诊断码、术语、停用句式） | **与主项目现有六项检查零差异**：同一快照、同一输入，逐条结论相同 |
| **M2 需求层** | `req new/change/verify/backfill`、签名、三条硬门禁、`trace` | 三个 fixture 全绿；故意改文本不升版本 → 红灯；`planned` 带锚点 → 红灯 |
| **M3 渲染** | `report`、`fmt --check`、`INDEX`／`DETAIL`／HTML、`--lang en` 回退 | 连续 10 次生成逐字节一致；缺 `*_en` 字段时回退中文并标 `(zh)` |
| **M4 切换** | 影子模式接入主项目 CI（只报告不阻断）→ 切门禁 → 删除被替代的旧实现 | 影子模式**连续 10 次零差异**后切门禁；删除后一次 `revert` 可完整回滚 |

里程碑之间不设日期（概念稿 §12）；M1 不达标就不进 M2——等价性是最便宜也最容易糊弄的一关。

## 7 两个已定接口

**① 主项目快照用 CI `git archive` 拉 `docs/`，不人肉复制。**

```sh
git archive <rev> docs AGENTS.md README.md | tar -x -C .snapshot/<rev>
```

理由：可复现（快照绑定提交号，同一 `rev` 永远得到同一份文件）、不会漂（不靠人挑文件，也不会漏掉新加的子目录）、不读工作区（本地未提交的改动不会混进对比）。代价是必须指定 `rev`，因此 CI 与本地调试都要显式传参，不允许「默认当前目录」。

**② 生成物只写到 docops 自己的 `out/`，由主项目 CI 校验一致性。**

理由：**依赖单向**——主项目只读、docops 只读主项目快照，谁都不写对方，主项目就不必为「工具可能改我文件」而放松只读。落地方式：主项目 CI 跑 `docops report` 后用 `docops fmt --check` 校验 `out/` 是否与仓库内留存的副本一致；要展示报告就把它当 CI artifact 发布，而不是提交文件。

## 8 反模式警告

- **工具不得内建主项目业务概念**。`M-xx`／`I-xx` 在工具眼里只是配置里的编号前缀与义务项列名；一旦它知道「事件必须有地点」，它就从通用检查器退化成定制脚本，第二个项目立刻用不了。
- **不做语义判断**。不内置分词、不判断「这条验收标准写得好不好」；那属于人工复核与真实模型验收。
- **不把判定塞进渲染**。渲染层一旦开始判断对错，同一规则就会有两份实现，且报告与门禁会给出不同答案。
- **不引入隐式默认**。缺配置项报错，不「猜一个合理值」；猜出来的默认值会在第二个项目上静默失效。
- **不让豁免变成后门**。豁免只压噪声，过期即失效（概念稿 §13），且永远不能覆盖硬门禁——这条要在 `gates.py` 里写成不可配置。
- **不把报告做成 KPI**。覆盖率图表一类的东西不做（概念稿 §14），一旦上墙就会被优化，而不是被使用。
